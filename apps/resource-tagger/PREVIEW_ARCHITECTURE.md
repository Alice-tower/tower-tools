# 内部预览扩展：现状与接入规范

版本：1.2.0。日期：2026-09-22。

本文记录当前实现和后续开发的工作基线。**规矩是死的，需求和代码是活的；这些约定随时可以优化。** 当实际插件证明某个接口或边界不合适时，可以同时修改宿主与插件，并同步测试和文档，不需要维护一个假想的外部插件生态。性能与功能完整性发生冲突时，优先保证功能完整性。

## 已实现与未实现

已实现：顶部“浏览方式”选择器；标准列表通过扩展入口运行；固定资源信息 Tab；可选浏览布局、详情 Tab、右键动作；独立预览队列；按需加载与取消辅助函数；路径校验；外部程序参数化启动入口；插件配置/缓存目录分区；插件错误与资料库错误分开显示。

正式注册的插件只有 `standard`（标准列表）。测试源码中的网格插件用于验证接入，不进入便携版。浏览方式仅在本次会话中保留，重启默认标准列表。资源数据库仍为 schema 2，本次没有数据库迁移或新增依赖。

尚未实现：漫画/图片/视频插件、内容解码、缩略图缓存及淘汰、相同内容请求合并、内部查看器、查看器设置界面、浏览方式持久化、文件实时监听。`cacheDirectory()` 目前仅提供目录位置，不代表已经具备缓存系统。首次实际插件开发时再确定这些能力的实现。

## 职责与代码位置

代码位于 `src/main/kotlin/dev/towertools/resourcetagger/`，保持单个 Gradle 模块。当前按源码文件组织，不为了插件概念单独建立模块、动态类加载器或二进制协议。

| 文件/类型 | 当前职责 |
| --- | --- |
| `LibraryApp` | 页面组装、筛选/焦点状态、公共工具栏与分页、表单与确认流程、选择当前插件 |
| `LibraryController` | 串行执行资料库操作；维持跨页选择；写操作刷新后递增预览修订号 |
| `ResourceBrowser` | 选择插件浏览实现；缺省使用标准列表 |
| `ResourceItemFrame` | 统一焦点、勾选、右键菜单外壳，供列表和网格复用 |
| `StandardResourceContent` | 名称、类型、Root、状态、标签、待处理信息的标准展示 |
| `ResourceDetails` | 固定信息 Tab 与插件 Tab；只组合当前激活的 Tab |
| `ResourceActions` | 原有导航、标签、确认、忽略、重新定位、数据库移除操作 |
| `PreviewPlugin` / `PreviewRegistry` | 三个可选扩展点和显式注册；校验插件 ID 唯一性；未知 ID 回退标准列表 |
| `PreviewRuntime` / `PreviewHost` | 应用级工作队列、插件会话、文件访问、存储目录、错误提示和动作执行 |
| `rememberPreview` | 可见项目或激活 Tab 的异步请求状态与取消 |

## 三个扩展入口

`PreviewPlugin` 声明 `id`、`title`，按需覆盖以下成员：

- `browser`：`PreviewBrowser`，接收 `BrowserContext`、`PreviewHost` 和宿主分配的 `Modifier`。不提供时自动回退标准列表。
- `tabs(target)`：返回 `PreviewTab` 列表。宿主始终保留 `information`（资源信息），该 ID 不允许被插件占用。
- `actions(target)`：返回 `PreviewAction` 列表，追加在管理菜单后面。管理繁忙或资源非可用状态时不提供插件动作。

插件和贡献项 ID 使用小写字母开头、后接小写字母/数字/连字符，最长 64 字符；同一插件的 Tab ID 和动作 ID 分别保持唯一。插件 ID 同时用于存储目录，修改时需要考虑已有配置。展示名称可以自由调整。

`tabs` 和 `actions` 在界面侧执行，必须仅根据已有元数据快速返回，不在这里枚举目录或读取文件。工厂异常与重复贡献 ID 会报告预览错误，管理区保持可用。插件的 Compose 内容属于受信任的应用代码，当前没有能够拦截任意 Compose 异常的隔离容器，也不是不可信代码沙箱。

## 主程序状态不能由展示方式暗中改变

`BrowserContext` 只包含当前页的 `BrowserItem`、勾选与焦点状态、焦点/选择回调和完整菜单提供器，不包含 `Library`、SQLite 连接或控制器。插件不拥有查询、总数、分页或跨页选择。

- 浏览方式切换保留筛选条件、页码、勾选集合和聚焦资源 ID。布局滚动位置与插件 Tab 状态可以重置。
- 插件展示当前页的全部匹配资源。不适用的资源使用普通展示，不能静默隐藏。以后如需“仅可预览”，应增加明确筛选并保证精确计数与全选一致。
- 自定义列表/网格复用 `ResourceItemFrame`。自定义内容至少保留名称、状态与必要的管理提示；优先复用 `StandardResourceContent`。
- “全选结果”仍由主程序查询全部匹配 ID，不能替换成当前页或可见卡片 ID。
- 插件内部页码、图片选择、缩放等属于插件局部状态，不能复用主程序的资源选择集合。
- 固定信息 Tab 保留全部原有信息及操作。插件只增加预览 Tab，不替换标签和状态管理。

当前接口没有阻止内部代码故意违反上述规则；这些是接入与测试约定。若某个真实插件需要不同交互，应先明确用户语义，再调整接口和测试。

## 扫描与内容预览分开

资源扫描继续只登记 Root 的直接子项，完整枚举成功后在事务中更新。预览按需读取某个资源内部的内容；其中的图片、章节等不自动成为资料库资源，不自动获得标签，不改变 Missing 或待处理状态。

后台任务先使用 `host.files.resolve(target)` 校验 Root、资源状态及磁盘对象类型，再访问内容。它返回受校验的资源路径，仍可能在读取时遇到外部删除等变化，应正常呈现读取失败。

当前接口只校验资源入口，不提供完整的内部目录遍历器。实际插件增加内部枚举时，需要明确是否递归、排序、Hidden/System/重解析点处理以及越界路径策略，不能直接把内容枚举混入 `LocalFileSystem.scan` 的资源登记流程。

`host.files.openExternal(target, executable, arguments)` 会再次校验资源，并使用参数列表启动外部程序，资源路径追加在末尾，不拼 shell 命令。当前支持的参数形态满足基础入口；特殊查看器若需要不同参数位置，可以在首个具体需求中调整。内部窗口尚未封装，未来可经 `host.onUi` 发布 UI 状态并明确其生命周期。

## 任务生命周期、性能和失败处理

每个应用实例的 `PreviewRuntime` 持有 2 个工作线程和最多 128 个排队任务。所有插件会话共享该队列，切换不会增加新的线程池。它与资料库单线程队列独立，队列满时返回可重试错误，不在界面线程执行工作。

每个插件会话使用一个 `PreviewHost`。切换插件、资料库写操作刷新、点击“刷新预览”时创建新会话并关闭旧会话；退出应用关闭工作队列。刷新按钮在非标准浏览方式下显示。

可组合预览使用 `rememberPreview(host, requestKey) { ... }`：

1. 在后台加载，返回 `Loading`、`Ready(value)` 或 `Failed(message)`。
2. 项目离开组合、切换资源或 Tab 时取消对应任务。
3. 取消/关闭后的完成回调不再发布到界面，即使底层工作没有响应线程中断。
4. UI 回调在 AWT 事件线程执行。插件动作在后台执行，需要 UI 操作时使用会话受控的 `host.onUi`。

请求键必须包含影响结果的资源/路径、预览参数和修订信息，不能只用固定字符串。插件用懒列表/网格按可见项请求，允许小量预取；不得因为主程序加载一页 200 条记录，就同步读取 200 个目录或解码所有原图。

取消是协作式的，不能强制终止忽略中断的解码器。此类工作仍可能占用两个工作线程，虽然不会回填旧结果或阻塞资料库操作。后续选择解码器时要处理中断、资源释放和超时，不应通过不断新建线程绕过问题。

动作和贡献工厂错误显示在预览错误区，加载错误由插件在所属卡片/Tab 展示；日志记录插件及请求/资源标识。预览失败不修改资源状态或标签，也不使用全局资料库 `busy`。插件 Compose 编程错误仍需通过测试修复。

## 存储与未来缓存

运行时目录：

```text
%LOCALAPPDATA%/Alice-tower/TowerTools/dev.towertools.resourcetagger/
  library.sqlite
  plugins/<plugin-id>/config/
  plugins/<plugin-id>/cache/
```

目录通过 `host.storage` 按需创建，应在后台任务中访问。构建只更新程序输出，不覆盖这些目录。插件不在原资源目录旁写缩略图或配置。

首个内容插件实现缓存时，再增加按内存/磁盘容量淘汰、相同请求合并、失败重试与内容变化失效。缓存键要考虑实际文件、更新时间/大小、预览尺寸和插件算法版本。不能仅依赖资源 ID，也不能假定目录时间戳包含内部文件的一切变化。没有实时监听时保留手动刷新，并说明缓存一致性边界。

## 接入和验证步骤

1. 新建一个 `PreviewPlugin` 实现，按需提供扩展点；在 `PreviewRegistry` 默认列表中显式注册。不增加主页面的插件类型判断。
2. 使用当前页上下文、公共卡片外壳、`rememberPreview` 及宿主文件访问能力。对不适用、空内容、读取错误分别提供明确展示。
3. 覆盖切换时的筛选/页码/勾选/焦点保留、跨页批量操作、无效路径、过期结果、Tab 惰性加载和失败后管理功能。
4. 如果插件新增图片/媒体依赖，按仓库规则核对实际打包内容和许可。
5. 更新本文与 README，区分已经可用的能力和规划；运行仓库构建脚本发布。

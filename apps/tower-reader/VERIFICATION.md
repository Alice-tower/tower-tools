## 1.2.0 微信读书

新增浏览器持久化、导航记录与 URL 范围测试。隔离的本地 HTTP 夹具验证隐藏/显示不重建网页，持久 HTTP-only Cookie 与 localStorage 跨 WebView2 实例重启保留；明确清除登录数据后两者均移除。导航状态跨 Controller 重启恢复；只打开本地模块时不创建浏览器，不保存登录回调查询参数。

真实微信读书网站测试通过环境变量 TOWER_READER_VERIFY_WEREAD=1 启用，离线构建可跳过这两项联网测试。本次发布启用了该开关。独立进程验证原生浏览器和实际 Compose 宿主、模块切换、隐藏后恢复同一页面、网页焦点下真实 F11/Esc 键盘事件及两轮全屏。截图采样同时要求网页内测试标记实际出现在屏幕上，防止白色占位区域被误判成网页正常。实际检查了站点登录二维码显示，并验证网页组件重新打开后能干净重建。截图位于 build/test-previews/weread-*.png，紫色小方块仅为隔离测试的显示标记，正式程序不注入它。

1.2.0 的最终完整 64 项回归启用了真实站点测试，隔离测试进程通过 WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--no-proxy-server 直连。此前自动化环境曾返回 ERR_CONNECTION_CLOSED，独立代理请求也出现 TLS 握手失败，而官网直连返回 200；随后仅从测试进程移除临时 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 变量，取消浏览器直连参数，默认浏览器配置的五项微信读书测试再次全部通过。未更改系统代理，也未在正式程序中强制直连。

原生 Chromium 子窗口不能通过 SwingPanel 的离屏绘制方式显示，最终直接嵌入 Compose 顶层 HWND 的指定内容区域；单独 STA 线程与 AWT 原生窗口线程连接输入队列后，网页焦点下的 F11/Esc 才能正常送达。退出时关闭控制器、释放 COM、断开输入队列，并等待此专用 profile 的浏览器进程退出。

本机运行库为 Microsoft Edge WebView2 Runtime 154.0.4258.48。部分正常退出会输出 Chromium 的 Chrome_WidgetWin_0 注销提示（错误 1411）；测试中进程退出与数据重开均完成，无 JNA 回调异常。尚未覆盖所有 Windows 显卡与多屏 DPI 配置。

网站账号的扫码需用户本人完成。自动测试验证的是浏览器持久化机制和真实站点登录入口，不代表已验证某个微信账号的服务器会话有效期。

## 1.1.1 全屏黑屏修复

补充真实 Windows 窗口的全屏回归后，复现了黑屏：JavaFX 场景快照与 JFXPanel 绘制缓冲仍有正文、文字位置和尺寸正常，但屏幕上阅读区域全黑。旧测试只切换 ReaderScreen 的全屏布局标志，未实际改变 Windows 窗口状态，因此漏掉了显示层问题。

启用 Compose 的 Swing 混合显示，并通过已有 JNA 修改顶层窗口边框和当前显示器范围；不再进入 Skiko 的原生全屏层。两个调整一起使用才能通过本机回归。切换不重建阅读面板、WebView 或章节，继续使用既有的预排与位置恢复。

独立 JVM 创建真实可见窗口，以屏幕截图同时检查纸张背景和正文像素；分别验证暖纸单页、深色双页，从普通窗口与最大化窗口多次通过 F11 进入全屏、左右键翻页、Esc 退出。检查全屏边界覆盖整个当前显示器、边框为零、阅读位置保留，并恢复原窗口边界与最大化状态。截图位于 build/test-previews/native-*.png。该测试要求交互式 Windows 桌面，不等价于所有显卡与多显示器配置的实机覆盖。

## 1.1.0 分类编辑与排序

新增四项回归测试：两项数据库测试覆盖已有分类迁移、排序恢复、新增及消失分类、分类整体改名和事务回滚；两项 Compose 界面测试使用真实右键与鼠标拖动，覆盖改名、取消、空名/重名提示、当前筛选保留、顺序持久化，以及 20 个分类之间的上下边缘自动滚动。故意让分类顺序更新失败时，关联书籍的分类更改会一并回滚，阅读进度、标题和文件信息保持原值。

## 1.0.3 界面与封面

书库固定暖纸色，进度位于封面左上角；Compose 交互测试用真实鼠标右键打开菜单，验证编辑、取消移出、确认移出及原文件保留。阅读只提供暖纸和深色。核对了书库、PDF 阅读和全屏截图。

PDF 页码移至右下角，单独对话框验证合法页码跳转，并拒绝 0 和超过总页数的输入。全屏时上下栏、页码、进度条均隐藏；界面测试确认没有中央“正在显示…”提示。当时的独立进程只通过窗口键盘分发切换全屏布局标志和按 Esc 返回，确认同一个 FlowPane 保持挂载、当前书籍不退出；真实 Windows 全屏显示另见 1.1.1 检查。

封面空白有两层原因：隐藏标题及嵌套容器干扰分页；loadContent 生成的 about:blank 页面无法读取 file: 图片。旧图片排版测试使用内嵌 data: 图片，未覆盖真实本地图片装载。现在后台写入本地页面文件后加载，保留内容过滤和 CSP；不把图片转为大块内嵌数据。16 次章节预排与切换验证本地图片实际加载、两个 WebView 复用，稳定时仅有两个页面文件，关闭后清理为零。

真实 WebView 分别验证嵌套图片封面及简单 SVG 图片容器：图片完整位于第一页，且没有多出空白页；另有四项解析回归覆盖隐藏节点、本地 SVG 图片转换、拒绝外部或复杂 SVG、仅在明确封面章节使用后备封面。用户 EPUB 在隔离书库中也验证了实际封面尺寸、可见范围和单页结果。

## 1.0.2 键盘与章节切换

窗口级键盘分发覆盖左右键、Page Up/Down、空格及 Shift+空格，并保留长按连续翻页；F11/Escape 的重复按下只触发一次。测试验证事件消费、不会被第二个处理器再翻一次、对话框和文字输入不受影响、关闭阅读器后注销分发器。WebView 键盘回退在使用窗口分发时关闭，其他场景也过滤 Ctrl/Alt/Meta。

连续切章的最新请求失败时，恢复最后成功显示的页面；若新章节正文已提交但尚未显示，则重新提交当前正文，不复用旧章节的位置。两项回归测试覆盖连续失败及尚未显示的章节恢复，预读后删除章节文件仍能正确报告错误。

三个全新 JVM 各自打开三章多页 EPUB，多次从正文、Compose 窗口和宿主面板分发左右键，验证恰好前进一屏并返回；跨章始终是原 FlowPane 实例。独立的缓冲测试预排并切换 16 个章节，65 次深色场景采样未发现白屏，确认只有两个 WebView，命中预排章节时复用同一个 Document，没有再次加载。

这些检查覆盖本次代码中的重建和白屏问题；采样不等价于对所有显卡、显示缩放和真实图书的连续录像验证。

## 1.0.1 首次打开卡死修复

从用户卡死进程获取的线程栈确认：AWT 界面线程在 JFXPanel.addNotify 中初始化 NodeHelper，等待 JavaFX Node；JavaFX 线程同时创建 WebView，初始化 Node 时等待 NodeHelper，形成类初始化死锁。EPUB 解析线程此时已经空闲。

修复将 WebView 创建延后到 Swing 组件挂载完成之后，避免两个线程并发进入这组类初始化。原先的 WebView 分页测试预先启动了 JavaFX，不能覆盖这一首次打开的竞态；新增测试在独立 JVM 中验证初始化顺序和完整 Compose 阅读界面，子进程超时会被终止并使测试失败。

此次用用户刚才打开的 EPUB 在独立临时书库中完成同样的回归流程，不修改原书库。该私有样本不加入仓库；通过 TOWER_READER_REGRESSION_EPUB 环境变量提供路径。未提供时只跳过这一可选样本测试，其余本地测试仍执行。

## 性能样本

下表保留 1.0.3 的性能样本；本次分类更新另有上述交互与持久化检查。

| 场景 | 本机结果 |
| --- | --- |
| 32,304,000 字节中文 TXT | 221 个小节，最大 48,832 个 UTF-16 单位 |
| TXT 首次建立索引 | 约 0.44 秒 |
| TXT 缓存重开 | 约 0.02 秒，仅索引和文件元数据 |
| 750 轮 WebView 操作 | 含 38 次字体或单双页重排，约 1.4 秒 |
| 重复操作后 JVM 堆 | 第 250 轮与第 750 轮 GC 后均约 20 MB，差值约 85 KB |
| 1000 页合成 PDF | 约 146 KB，共用一张 128×192 扫描图 |
| 合成 PDF 打开 / 首屏渲染 | 约 13 ms / 18 ms |
| PDF 100 次交替跨页访问 | 峰值输出图片缓存 99,840,000 字节，低于 96 MiB 上限 |
| PDF 关闭 | 输出图片缓存计数和字节归零 |

这些夹具检验的是有边界的加载、分页和缓存机制。合成 PDF 不等价于每页都有复杂矢量或高清扫描图的真实大文件；JVM 堆数字不包括 JavaFX WebKit、Skia 等原生内存。尚未进行数小时的人工连续阅读，不把自动重复测试描述为长期实测。

每次构建后的原始报告位于 build/verification/，测试结果位于 build/reports/tests/test/，图片位于 build/test-previews/。上述构建数据不提交 Git。

## 实际便携包

通过已打包的 1.2.1 TowerReader.exe --verify-runtime 在新的隔离目录执行检查，进程退出码为 0，报告 PASS。验证了随包 JVM、Skiko 原生库、SQLite、GB18030、TXT、EPUB、PDF、JavaFX WebView 和 Java/JavaScript 位置回调，恢复文字位置 800；同时确认实际本地 EPUB 图片已加载。精简运行时包含所需的 jdk.unsupported.desktop；最终 stderr 没有异常堆栈。

JavaFX 在非模块化 JVM 应用中输出一次“classes were loaded from unnamed module”提示；当前应用以类路径方式部署，相关渲染和桥接检查已通过。

本地阅读期间没有下载阅读组件；本地书内外部资源与脚本不会被载入。微信读书页面需要联网并使用网站自己的脚本。便携包内同时保留第三方许可与 OpenJFX 源码分发包。
